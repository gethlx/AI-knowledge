## 二、此前问题是否意外回退

### F-01：light 静默对伪装成模型拒绝

**未回退。**

§2.5 明确 `LIGHT_SILENT_EXCLUDED`：

- 不进入正式图；
- 不获得任何模型裁定状态；
- 不得转换为 `REJECTED_MODEL_ADJUDICATED`。

§2.5.1 又规定了有效争议、静默排除和失败状态，状态边界比 v2.3 更清楚。

### F-02：4,051 个候选覆盖不足

**未回退，但仍属于经明确授权的范围偏差，不是原 P5 全量复核要求本身已被满足。**

v2.4 保留：

- 4,051 行逐对台账；
- 互斥、完备、计数一致；
- full、light、争议转 full、静默排除和失败挂起状态；
- §2.5 的明示偏差声明；
- M-4 要求主公终批批准后方可执行该偏差。

因此，记账覆盖已经闭合；但 2,282 个 light 对仍不取得完整三路模型裁定。这个事实必须继续在 P5 报告和 P8 发布说明中披露，不能表述为“4,051 对全部完成三路模型复核”。

### F-03 / N-01：blocking 通过后门

**未回退。**

§4.3 只保留：

```text
open | fixed | escalated
```

§4.4 仍要求 blocking 只能通过：

1. 修复、重审、重建图并重新复审；
2. 升级 `ESCALATE_HUMAN`，并按主公裁决缩小发布范围、重建新图、重新执行 P7 和 P7.5。

`waived_by_owner` 已删除，没有重新出现等价后门。

### F-04 / N-02 / N-03：P7.5 容量、失败恢复和协议衔接

**未回退。**

v2.4 保留并强化：

- 单次全图调用；
- 禁止分块；
- Tier0/Tier1 确定性压缩；
- 12 万字符硬上限；
- 超限直接 `P75_FAILED`；
- 幂等键；
- 300 秒超时；
- 3 次重试，0/60/120 秒退避；
- 连续 2 次失败熔断；
- 同一图版本完整重跑；
- 不使用 `ADJUDICATION_DEFERRED` 处理图级任务。

需要强调：8.5-G 仍是“随本升级案终批一并授权”的正式例外协议。在主公终批前，不能实际启用 P7.5 图级特化调用。

### F-05：P7.5 与逐对裁定、高影响项衔接

**未回退。**

§4.1 明确 P7.5 是附加的全局审查，不替代：

- 14号逐对裁定；
- 核心课程入口和关键路径的高影响项复核；
- 14号边级重审或人工升级流程。

blocking/suggestion finding 必须映射至有效 `edge_refs` 或 `pair_refs`，然后经原有流程处置并重建图。

### F-06：结构分区可复现性

**未回退。**

§2.1 固化了：

- `greedy_modularity_communities`；
- 输入候选池；
- 脚本；
- 参数和随机种子；
- 逐对 `unit_ledger`；
- 单元互斥、完备、计数一致校验；
- U6 的桥接审查定位。

### F-07 / N-04：接力、租约和盲评隔离

**未回退，且 M-2 已补强。**

§2.2 同时保留：

- 原子临时文件落盘；
- O_EXCL 原子 claim；
- 租约过期和重领；
- 残留临时文件清理；
- reviewer 级独立会话；
- 禁止读取其他 reviewer 文件、汇总状态、裁定队列和错误日志；
- `relay_log.jsonl` 隔离校验；
- 双进程竞争测试。

### F-08：v1 意见继承风险

**未回退。**

§2.3 仍将约 300 个混合来源对限定为逐条完整核验；其余约 1,200 份保留为“程序校验 + P5.0 初筛”的风险受控折中，并明确这不是完全兼容性证明。该风险没有被重新包装成已完全解决。

### F-09：P5.0 探针代表性不足

**未回退。**

§2.4 仍将 20 对分层探针定位为异常初筛，而非普遍兼容性证明，并规定四项指标、失败阈值、扩样和暂停回炉路径。

### F-10 / N-06：findings 结构和引用完整性

**未回退。**

§4.3 固定了顶层包络：

```json
{
  "p75_id": "...",
  "graph_version": "...",
  "review_input_hash": "...",
  "input_tier": "...",
  "findings_total": 0,
  "findings": []

```

并规定：

- `findings_total` 必须等于数组长度；
- blocking/suggestion 必须有有效边引用；
- 引用必须属于被审 `graph_version`；
- findings 必须有处置状态、责任人、修复和复审记录。

### F-11：成本和调用统计

**未回退。**

§六继续要求记录：

- 调用次数；
- 重试和失败；
- 输入输出字符量；
- deferred 数；

### F-12：LightRAG 与正式图边界

**未回退。**

§三明确 P7 从 `accepted_model_adjudicated_edges.jsonl` 建图；§4.1明确 P7.5 只审正式裁定图。LightRAG 未核验关系不进入正式图，也不参加正式边一致性验收。

### F-13：回滚和不可变工件

**未回退。**

§4.4明确回滚目标是不可变工件；P8 需记录发布包文件名和文件哈希，而不是只记录逻辑版本号。

## 三、仍需指出的边界事项

这些不构成 M-1～M-4 未解决，但执行时必须严格遵守：

1. **主公终批尚未等同于本次 sol 四审。**  
   v2.4 自己规定了生效前置条件。即使本四审判定通过，在主公批准 §2.5 偏差和 §4.2 的 8.5-G 之前，不能启动依赖这些条款的 P5/P7.5 执行。

2. **“依据不足”的两处仍应保持披露。**
   - v1 其余约 1,200 份意见的完整调用链兼容性没有逐条证明，只能按风险受控折中处理；
   - 20 对 P5.0 探针没有足够统计依据证明整体来源兼容，只能作为异常初筛。

3. **压缩算法已确定，但实现仍须测试。**  
   规范已足够定义行为；上线前仍应由程序测试验证：
   - 同一输入重复运行产生相同 `review_input_hash`；
   - 不发生模型改写；
   - 不发生静默截断；
   - Tier1 超限确实进入 `P75_FAILED`；
   - Unicode 字符计数与实现一致。

4. **light 失败不是静默排除。**  
   `LIGHT_REVIEW_INCOMPLETE` 不属于 P5 三个完成终态。若存在该状态，P5 不能宣称完成，必须补跑或保持挂起。

# 四、最终裁定

## **通过（可执行）——有前置生效条件**

v2.4 已解决三审遗留的 M-1～M-4，且未发现此前已解决问题发生实质回退。文本已经具备执行所需的：

- light 例外复核定义；
- 原子领取和并发防重复机制；
- P7.5 确定性压缩及超限失败路径；
- 偏差生效的主公终批硬闸门；
- 逐对、图级、发布级的审计闭环。

但这里的“通过”不是“立即无条件执行”。生效前必须完成以下主公终批确认：

1. **明确批准或拒绝 §2.5 的 light 偏差声明**  
   即允许部分正式候选通过 `LIGHT_SILENT_EXCLUDED` 路径，不取得完整三路模型裁定，并不得进入正式图。

2. **明确批准 §4.2 的 8.5-G 图级特化协议**  
   包括：
   - 单次 300 秒超时；
   - 3 次调用；
   - 0/60/120 秒退避；
   - `P75_FAILED`；
   - 连续 2 次失败熔断；
   - 同一幂等键复用；
   - 禁止分块；
   - Tier1 后超 12 万字符直接失败。

3. **形成正式终批记录**  
   至少包含：
   - 主公决定编号；
   - 批准时间；
   - 批准范围；
   - 被批准的偏差和特化协议；
   - 对未覆盖 light 对的发布披露要求。

4. **主控在终批记录落盘前不得执行依赖条款**
   - 不得把 light 对记为 `LIGHT_SILENT_EXCLUDED`；
   - 不得启动依赖该状态的 P5；
   - 不得以未授权的 8.5-G 参数执行 P7.5。

**最终意见：v2.4 可批准生效，但必须先取得上述主公终批记录；在终批完成前，不得按 v2.4 实际执行。**
