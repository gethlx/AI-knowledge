## 一、更正：我错在哪

初版的核心论点是：

> 「我们的总纲已经是结构化卡库，573 条边**已经声明好了**，抽取环节多余且有害，所以 GraphRAG 系整体不适用。」

**这条论点的一半是真的，另一半是自杀。**

| 我当时的说法 | 事实 |
|---|---|
| 「573 条边已经声明好了」 | ❌ **这 573 条一条都没核验过，是作废数据**。我一边给它标 `〔不可信〕`，一边拿它当"输入已就绪"的证据 |
| 「总纲是结构化卡库」 | ✅ 前半句成立，但结构化的**只是节点**，不是边 |
| 「抽取环节多余」 | ❌ **反了**。既然没有可信的边，抽取（或者说"建边"）根本不是冗余，而是**唯一还空着的那一步** |
| 「GraphRAG 系整体不适用」 | ❌ **这个结论下得太早**，而且理由是错的。它"不适用"的真实原因不是"我们不缺边"，而是"**它造出来的边照样不可信**" |

**一句话**：我用一堆自己刚宣布作废的数据，去论证"我们不需要造数据的功能"。这是逻辑上自我拆台。

## 三、结论反转：真问题不是"选哪个工具"

初版花大量篇幅比较工具。**那些比较现在大部分是无效的**——因为工具要解决的那个问题（建边），我们连"什么才算对"都还没定义。

### 3.1 所有工具都会替你造边，但造出来的边**依然不可信**

| 造边方式 | 代表工具 | 造出的边是什么 |
|---|---|---|
| LLM 从定义文本抽取依赖 | GraphRAG 系、docling-graph、llm-graph-builder | **AI 推测** |
| 共现 / 相似度统计 | rahulnyk/knowledge_graph、NoteConnection 的混合推理 | **统计相关**（相关 ≠ 先修） |
| 名称/编号匹配 | 自建脚本、模板匹配 | **字符串巧合** |
| 人工声明 | —— | **教学判断**（唯一可能可信的） |

**把 388 条"来源不明的未核验边"换成 200 条"AI 生成的未核验边"，这不是进步，是换了个生产厂家。**

这就是为什么原本那 388 条会烂在那儿两年：**"学完 A 才能学 B"是教学判断，不是文本相似度问题。** 机器从「精确定义」里读得出"A 的定义里提到了 B"，但读不出"A 是不是 B 的前提"。**前者是共现，后者是课程设计的决断。**

### 3.2 所以「自动生成知识图谱」这个命题，在当前输入下是**空的**

- 自动生成**节点**：不需要，197 张卡已经在。
- 自动生成**边**：能，但**生成出来的边和被你毙掉的那 388 条，可信度同级**。
- 那么"自动"生成出来的图谱，**唯一价值就是好看**。

**而"好看"恰好是本次最大的风险**——它会把一堆推测包装成专业图表，让人误以为已经验过了。

## 五、现在能做的 vs 不能做的

### ✅ 能立刻做，而且诚实：**分类视图**（不是依赖图）

按**字段里客观存在**的标签分组，不需要任何推测：

| 视图 | 依据字段 | 说明 |
|---|---|---|
| 认知层级视图 | 认知层级 | 识记 → 理解 → 应用 → 分析评价。**这是"难度梯度"，不是"先修关系"** |
| 知识标签视图 | K1–K6 | 人类·智能·机器／数据·表征·知识／… |
| 学习场景视图 | S1–S7 | 认识AI／使用AI／核验AI／共创／探原理／造应用／论影响 |

**关键**：以上分组是**分类（taxonomy）**，不是**依赖（dependency）**。它回答"这个知识点属于哪一类、讲到多深"，**不回答"必须先学哪个"**。不能拿它冒充图谱。

### ❌ 现在不能做：**依赖图谱**

因为：
1. 边不存在；
2. 自动造的边不可信（见 §3.1）；
3. **可信的边只能来自教学判断**——要么人工重建，要么拿到母版 `v5.0-r4` 逐条比对（母版不在本地）。

### 🔧 那套"自建脚本"还有用吗？

**有，但降到第二阶段。** 一旦边可信了，下面这套立刻能复用（都是机械劳动）：
```
cards.json → 边归一 (from=前置, to=后续) → 不对称检测 → 环检测
          → 拓扑分层 → CIS 关键度打分 → graph.json + 分层表 + vis.js 交互页
```
**现在做，只是给一堆不存在的边盖个漂亮的房子。**

## 七、唯一正解

> **先解决"边从哪来、凭什么可信"，再谈工具。**
>
> 在此之前，任何工具选型都是伪问题；任何"自动生成的知识图谱"都只是给未验证的推测配一张好看的皮。

**边的可信来源只有两条**：

| 路径 | 前提 | 成本 |
|---|---|---|
| **人工重建** | 需要懂教学的判断者逐条过 | 197 个点、潜在约数百条边，工作量最大但唯一自足 |
| **母版比对** | 需拿到母版 `v5.0-r4`（声明为 CONFIRMED 的权威来源） | 若母版含先修关系定义，则**一次到位**，成本最低 |

**我建议先确认母版里到底有没有先修关系的权威定义。** 如果有，这条路最省；如果没有，就只能人工。
