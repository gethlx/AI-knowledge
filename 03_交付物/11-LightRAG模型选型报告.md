# 11 - LightRAG 模型选型报告（7 选 3 + 对话模型裁定）

> 日期：2026-09-13
> 任务：从 5 个自定义对话模型 + 2 个向量模型（共 7 个）中，为 LightRAG 知识图谱构建选出最优模型组合；并裁定本任务对话模型用 glm5.3flash 还是 gpt5.6sol。
> 证据来源：Vimox SDK 文档（/tmp/vimox-sdk/）、`/v1/models` 实时价格、双向量模型实测、LightRAG 社区反馈（WebSearch）、本任务 46K tokens 摄入文档的实测结构。

---

## 一、结论（先说答案）

| 角色 | 选定模型 | 一句话理由 |
|---|---|---|
| **向量（Embedding）** | `glm-embedding-3-pro`（4096 维） | 实测全面碾压对手：中文区分度更高、快 5 倍、便宜一半 |
| **抽取（Ingestion LLM）** | `gpt-5.6-luna` | 社区口径：抽取用快而便宜的非思考模型；它是 7 选里最便宜的对话模型 |
| **查询（Query LLM）** | `gpt-5.6-sol` | 社区口径：查询要强模型消化长噪声上下文；sol 是质量/价格/速度的最优平衡点 |
| **本任务对话模型** | **保留 glm5.3flash，不换** | 对话编排不是质量瓶颈；gpt5.6sol 的价值该花在 Query 角色上，别浪费在陪聊上 |

## 三、向量模型：glm-embedding-3-pro 完胜（实测数据）

用课程真实语料构造三组样本（同概念复述 / 无关概念 / 同域近邻概念）测余弦相似度：

| 指标 | glm-embedding-3-pro (4096维) | gpt-text-embedding-3-large (3072维) | 谁赢 |
|---|---|---|---|
| 同义区分（同对相似度，越高越好） | **0.737** | 0.656 | glm |
| 异义分离（异对相似度，越低越好） | 0.206 | **0.058** | gpt |
| 同域近邻区分（同域对 vs 异对的对比度） | **0.533**（0.737-0.206） | 0.396（0.656-0.058 的判别边际更弱） | **glm** |
| 速度（6 条文本） | **2.7s** | 14.5s | glm |
| 价格 | **50** | 94 | glm |

判读：异义分离 gpt 压得更低，但知识图谱检索的真正难点是**同域近邻概念的区分**（"机器学习" vs "深度学习"），glm 的对比度明显更好。加上 5 倍速度和近半价格，**glm-embedding-3-pro 严格占优，无争议**。

## 四、LLM 角色：社区反馈 + 任务要求交叉验证

### 社区共识（LightRAG 官方 issue /讨论区高频结论）

1. **抽取（ingestion）用快、便宜、非思考模型**——抽取是逐 chunk 的高频调用，token 消耗大头在这里；思考型模型又慢又贵且对结构化抽取增益有限。
2. **查询（query）用强模型**——查询时要消化检索回来的长且噪的上下文做答案生成，这是质量敏感点，调用频次低，值得用贵的。
3. **中文语料抽取需要足够模型规模**（社区经验 32B+ 起），太小会漏抽/错抽。
4. 关键词提取（keyword）是轻量任务，非思考模型即可（luna 一并覆盖）。

### 对照本任务

- 摄入文档 ≈ 46K tokens，抽取输出约为输入的 1-2 倍 → **全量 197 卡跑一次抽取的成本估算**：
  - luna：约 6.6（输入）+ 77（输出）≈ **~84 ViMoney**
  - sol：约 33 + 386 ≈ **~420 ViMoney**（5 倍）
  - astra：约 82 + 486 ≈ **~570 ViMoney**（7 倍）
- 抽取结果反正要过**人工裁决**（09 号报告口径：AI 提议 + 人裁决），抽取模型不必最强，够稳够快即可——**这直接否决了用 astra/opus-5 做抽取的必要性**。

### 定案

| 角色 | 选定 | 备选（何时启用） |
|---|---|---|
| 抽取 | **gpt-5.6-luna** | 若 luna 对 197 卡规范名对齐效果差（漏用卡号），升级为 sol 重跑 |
| 查询 | **gpt-5.6-sol** | 终版深度问答/汇报生成可临时切 claude-opus-5 |
| 向量 | **glm-embedding-3-pro**（dim=4096） | 无 |

## 五、对话模型裁定：glm5.3flash 不换

**结论：继续用 glm5.3flash，不切 gpt5.6sol。**

理由三条，直给：

1. **对话编排不是本任务的质量瓶颈。** 当前任务的难点在「边从哪来」（人工裁决流程）和「抽取对齐」，不在对话模型智商。glm5.3flash 到目前为止的编排、脚本、调研没有掉链子，换模型属于花钱买安慰。
2. **gpt5.6sol 的每一分溢价都该花在 Query 角色。** 它在 LightRAG 里当查询模型是刚需（长上下文消化），同时兼职对话是冗余配置——同样的钱，花在刀刃上一份就够。
3. **真到要强对话的场景（如人工裁决时的深度推理辅助），临时切 sol 一次即可**，不需要常驻更换。
