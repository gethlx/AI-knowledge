### 2.2 单元内会话接力协议（F-07/N-04 修订版）

- **单元 = 语义边界**，**会话 = 接力班次**；班次大小由首单元实测吞吐定；
- **原子落盘**：意见先写 `<pair_id>/{reviewer}.json.tmp`，再原子重命名；
- **领取租约（原子独占，F-07 三审收口）**：领取槽位时必须以**原子独占方式创建**声明文件 `<pair_id>/.claim.{reviewer}`（实现 = `os.open(path, O_CREAT|O_EXCL|O_WRONLY)` 或等效原子创建；**禁止**"检查存在→再写入"两步式）：
  - 目标意见文件已存在且为有效 JSON → 跳过；
  - `.claim` 创建成功 → 领取成功，写入会话标识 + 领取时间戳；
  - `.claim` 创建失败（EEXIST）→ 读取其中时间戳：未过期（<30 分钟）→ 跳过；过期 → 删除旧 claim 后**重新以 O_EXCL 创建**（仍失败则再跳过，下轮再试）；
  - 残留 `*.tmp`（mtime 超过 TTL）→ 视为遗弃，删除后重试；
  - 落盘成功后立即清除自己的租约文件；
  - **并发测试**：上线前以双进程并发领取同一槽位做一次验证，结果必须恰为一方成功；
- **失败槽位状态**：`*.tmp` 一律视为未完成；`.claim` 过期 = 可重试；两者都不携带任何"已完成"语义；
- **reviewer 级盲评隔离（N-04）**：每个 `unit_id × reviewer_id` 班次使用独立会话；会话仅可读取冻结卡文、规则头、Schema 与**该 reviewer 自己的**任务状态（自己的 `.claim` / 自己的已落盘文件）；**禁止读取其他 reviewer 的任何文件、汇总状态、裁定队列或错误日志**；隔离遵守情况记入 `relay_log.jsonl`（含班次起止、领取/跳过/遗弃明细、吞吐、隔离校验结果）；
- **U6 输入体量校验**：送审前实测记录；超限按 §2.1 子批预案处理。

## 四、P7.5 图级整体审（强制闸门）

### 4.1 定位与边界

- P7.5 是**附加的全局审查，不替代 14号 逐对裁定与核心高影响项复核**；每条涉及具体边的 blocking 发现**必须映射到原 pair_id / edge_id**，经 14号 重审/升级流程处置后重建图并复审；
- **边级发现强制校验**：任何 blocking/suggestion 级 finding 必须至少含一个有效 `edge_refs` 或 `pair_refs` 项（存在于该 graph_version），否则完整性校验失败（F-05 遗留收口）；
- **审查对象 = 正式裁定图**；LightRAG 未核验关系不进输入、不做一致性验收（F-12）。

### 4.2 任务规格与 8.5-G 图级特化协议（F-04/N-02/N-03 修订版）

**8.5-G 特化协议（随本升级案终批一并授权，作为 14号 §8.5 的图级任务正式例外条款）**：

| 项 | 规格 |
|---|---|
| 适用范围 | 仅图级任务（P7.5）；逐对裁定仍走 8.5 原协议 |
| 幂等键 | `sha256(graph_version + p75_prompt_version)`；重试复用同一幂等键，不重复计费 |
| 超时 | 单次调用 300 秒（依据：sol 长文实测 233.6s/251.6s 成功、240s 曾超时） |
| 重试 | 3 次，退避 0/60/120 秒 |
| 失败状态 | 独立 `P75_FAILED`（**不使用** `ADJUDICATION_DEFERRED`——deferred 语义属于逐对裁定） |
| 熔断 | 连续 2 次 P75_FAILED → 暂停并向主公报告（图级单任务，不适用 10 对阈值） |
| 恢复 | 排除故障后对同一 graph_version **完整重跑**；产生新输入哈希则幂等键随之更新 |

**容量与压缩阶梯（N-02 收口：单次调用，禁止分块）**：

- 输入构成：全图（节点+边+方向）+ 节点摘要 + 边裁定理由摘要 + P7 机械校验结果；
- **压缩阶梯（三审必须修改项第 3 条：算法确定性化，禁模型改写）**：
  - **生成规则（程序化，规则版本 p75-compress-v1，随 manifest 固化）**：边理由摘要取 P6 裁定记录的 `reason` 字段原文；超限时按句号/问号切句，从首句起依序保留至字数上限——**只删不加不改写**；字数计算 = Unicode 字符数（`len()`）；节点摘要同样规则化截取；
  - Tier0 = 每边理由 ≤80 字；Tier1 = 每边 ≤40 字 + 节点摘要仅保留定义与度数；
  - **确定性保证**：同一 graph_version + 同一 Tier → 逐字节相同的送审输入，`review_input_hash` 可复现；
- **硬提交上限 = 12 万字符**：Tier1 后仍超限 → 直接 `P75_FAILED`（附体量报告），**不存在分块路径**——P7.5 自始至终定义为 sol 单次全图整体审，跨块全局问题不可见的风险不可接受；
- 禁止静默截断；实际送审字符数与所走 Tier 记入 findings 回执。

### 4.3 findings 输出 Schema（F-10/N-06 定稿）

顶层包络固定：

```json
{
  "p75_id": "sha256前12位（幂等键）",
  "graph_version": "被审图内容哈希前12位",
  "review_input_hash": "实际送审输入sha256",
  "input_tier": "tier0|tier1",
  "findings_total": 0,
  "findings": []
}
```

- `findings_total` 必须等于 `findings` 数组长度，否则完整性校验失败；
- 单条 finding：

```json
{
  "finding_id": "F-001",
  "level": "blocking|suggestion|informational",
  "edge_refs": ["edge_id 或 pair_id"],
  "node_refs": ["card_id"],
  "reason": "...",
  "evidence": "...",
  "disposition_status": "open|fixed|escalated",
  "owner": "orchestrator|human",
  "fix_record": "...",
  "recheck_result": "...",
  "related_graph_version": "..."
}
```

- **`disposition_status` 仅三态**（N-01 收口：`waived_by_owner` 已删除）；
- 校验规则：blocking/suggestion 级必须 `edge_refs` 或 `pair_refs`（即 edge_refs）至少一项非空且存在于该 graph_version；`edge_refs`/`node_refs` 不得同时为空。

### 4.4 blocking 处置与发布闸门（F-03/N-01 收口）

- blocking 关闭**仅两条路**：
  1. **fixed**：有记录的修复 + 受影响边经 14号 流程重审通过 + 重建图（新 graph_version）+ 对新图完整重跑 P7 机械校验与 P7.5；
  2. **escalated**：升级 `ESCALATE_HUMAN` 由主公裁决；主公若裁定"缩小发布范围"，属于 escalated 的处置结果——必须形成主公批准记录（决定编号+时间+被排除边清单），被排除边移出图、重建**新 graph_version**、新图完整重跑 P7 与 P7.5 后方可发布；
- **不存在第三条关闭路径**；禁止仅修改分级标签或状态字段清零；降级（blocking→suggestion）必须附证据记录与责任人，且由主控在报告中标明；
- 发布闸门：存在 `open` 状态 blocking → P8 不得执行；
- **回滚目标 = 不可变工件**（P8 发布说明记录回滚指向的发布包文件名 + 文件哈希，不使用逻辑版本号）（F-13 收口）。
