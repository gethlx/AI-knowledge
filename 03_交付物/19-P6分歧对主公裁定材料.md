```
## 裁定规则
1. 判定类型（relation_type）：prerequisite（先修）/ related（相关）/ no_relation（无关）/ insufficient_evidence（证据不足）。
2. 先修唯一定义：**不理解 A 会实质阻断对 B 的理解或应用**（缺失即卡住、卡文可证、方向唯一合理）。有帮助但非必需、同主题、共现、教学编排顺序、分类包含——都不是先修，是 related。
3. direction 仅 prerequisite 需要：source_to_target = A→B（先学 A 再学 B）；target_to_source = B→A。其余判定 direction 填 null。
4. 不偏向多数：三路中孤立的少数意见若理由扎实（卡文可证），应认真对待。
5. 证据不足时判 insufficient_evidence，不要硬猜。
6. 全部 41 对必须逐一给出裁定，不得遗漏。

## 输出格式（只要一个 JSON 对象，无 markdown 包裹、无其他文字）
{"1-01__4-08": ["related", null, "应用与工具的关系，非先修"], ...}
即 {"pair_id": ["relation_type", "direction或null", "≤30字理由"], ...}

```
