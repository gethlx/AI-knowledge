## 修复一 · 重新选回已读概念覆盖上一条历史（57号必修）

**根因确认**：56号在 renderNeighbors 恢复块加的 `syncHistoryStateNow()` 是越界写入——selectConcept 流程中该块执行时 URL 与当前历史条目仍属上一概念（如3-07），而 selected 已换成4-03，快照因此把3-07条目覆盖成4-03；pushState 无法补回。

**改动**：**删除恢复块中的 syncHistoryStateNow()**（恢复只改 DOM，不写历史）。selectConcept 流程的状态保存回到既有正确位置：`selected` 改变前 `replaceState` 写旧条目（L158），之后 `pushState` 建新条目。恢复 DOM 引发的 open 属性变化由新增的 MutationObserver 在**导航流程同步栈完成之后**（微任务级）触发，此时写入的是新条目且与条目 state 幂等，不再有越界窗口。

## 修复二 · 快速导航丢展开状态（57号F2）

**改动**：**放弃依赖异步排队的 toggle 事件，改用 MutationObserver（微任务级）作为 open 属性/相邻清单变化到历史写入的同步通道**：

```js
new MutationObserver(muts => { if (muts.length) syncHistoryStateNow() })
  .observe(document.body, { subtree: true, attributes: true, attributeFilter: ['open'], childList: true });
```

- 覆盖**用户点击 summary** 与**程序设置 open** 两条路径；回调在微任务中执行，早于任何后续任务（包括导航）——57号"收起后不额外等待即后退"的时序下，状态已在 goBack 发起前写入当前条目。
- 移除原 toggle→syncNow 监听（被 observer 全覆盖，避免双写）。
- 滚动/相机保持 250ms 节流不变；56号披露的 toggle 异步派发边界随之消除——不再依赖任何固定等待。
- 恢复 DOM 引发的属性变化（renderNeighbors 恢复块）在 popstate/selectConcept 同步栈完成后经 observer 写入当前条目，snapshot 与条目 state 一致，幂等无副作用。
