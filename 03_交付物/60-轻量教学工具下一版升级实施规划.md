# 60 · 轻量教学工具下一版升级实施规划

2026-10-19。用户要求将“主题导航＋变更摘要”作为下一版升级迭代，先形成实现规划。**当前状态：规划完成，尚未实施、验收或发布。** 本文件是下一轮执行入口，59号仍是已有本地候选的通过结论。

## 目标与交付

维持手机上“找到概念→读懂说明→探索关系→继续阅读”的轻量教学用途。维护者能够低频修改概念和关系，快速看清修改结果。下一版只增加两个能力，并补相称的现有测试：

| 交付 | 使用者 | 完成后的结果 |
|---|---|---|
| 主题导航 | 读者 | 在目录、搜索和三维关系网中按六个知识主题浏览，一键回到全部 |
| 本地变更摘要 | 维护者 | 指定前后两份数据，查看概念内容及关系的增删改与基础数据问题 |
| 相关回归验证 | 开发者 | 筛选、数据对比和已有历史状态不会因升级失效 |

沿用当前阅读和三维组件，局部修改有需要时可重写其负责部分；不以保持现有代码作为硬约束。本轮不重做视觉稿、不改写197条知识内容、不重建关系、不增加问答或管理后台；不用新增账号、服务器、模型服务和数据库。Graphify借鉴分组图例、图差异的设计，不安装整包；现有Playwright足够，无需另装MCP、Workspace CLI或Jev Guard。

- 搜索目前按中文/英文名称匹配、可筛认知层级；下一版在此基础上与主题条件求交集，不扩大为全文/语义搜索。
- 定义、原有解释字段、通俗解释及G_v2关系都有现有来源；preview-data只是页面副本。当前事实源不因新增UI改变。后续有意修订内容/关系可另按维护任务执行，摘要负责如实识别变化，不把现有结论设为不可修订。

## 功能一：主题导航

### 内容与入口

采用单选，共“全部”＋六个主题；显示主题名称及该主题概念总数，不向读者显示内部K编号或卡号。名称沿用现有课程知识分类：

| axis | 主题 | 当前数量 |
|---|---|---:|
| 1 | 人类、智能与机器 | 20 |
| 2 | 数据、表征与知识 | 22 |
| 3 | 算法、模型与学习 | 40 |
| 4 | 生成式AI、交互与智能体 | 47 |
| 5 | AI应用、工程与创新 | 27 |
| 6 | 社会、伦理与未来 | 41 |

数量从当前节点数据计算，不把表中数字写死。颜色使用一套固定的六主题映射，与目录标记一致；当前选中概念继续采用暖金高亮。主题不是学习阶段或固定学习顺序。

关系网展开时提供一个紧凑“主题：全部/主题名”按钮；打开简短主题列表，避免七个长名称挤占图谱空间。搜索/目录面板提供同样的主题选择，复用一个主题状态。阅读首屏保持正文＋缩略入口，不额外常驻一整排筛选控件。选择后关闭选择列表并保留可访问焦点。

### 明确的筛选规则

| 操作或状态 | 预期行为 |
|---|---|
| 首次打开 | 全部主题；已有深链仍打开对应概念 |
| 选择主题 | 目录/搜索只列该主题；关系网显示该主题节点，连线仅当两个端点都可见时显示；不夹带“只有一个端点可见”的悬空线或箭头 |
| 主题下搜索 | 主题、名称查询、认知层级条件同时生效；结果数量独立显示，主题总数不随搜索变化 |
| 无匹配 | 说明当前主题内没有匹配项，提供明确“清除筛选”操作，恢复全部主题和全部层级，保留搜索词 |
| 筛选后当前概念不在主题内 | 不改正文、不换概念；图旁显示“当前概念不在此主题”，提供“显示全部”；隐藏节点不保留视觉标签或键盘命中 |
| 从相邻概念等入口打开主题外概念 | 自动恢复全部主题后更新选择并单次定位，避免正文与图上选择不一致；不悄悄换到另一主题 |
| 全部主题 | 197节点/1562关系完整恢复；无数据删除或关系重算 |
| 浏览器前进/后退 | 恢复对应历史条目的主题、概念、正文展开、滚动及相机；旧条目没有主题字段时按全部处理 |

筛选仅改变显示，不重启力学、不重建节点对象或重新播种坐标。选主题时一次框定可见节点；“全景”拟合当前可见范围，“定位当前概念”在选中节点不可见时先恢复全部；用户随后可自由移动，不持续锁定。恢复历史时以保存相机为准，不再自动框定覆盖相机。

图旁显示“本主题X个概念/Y条主题内关系；跨主题关系在全部中查看”，不要让读者误以为未显示的跨主题关系不存在。相邻概念清单保持当前概念的完整真实邻接，不因主题筛选裁剪；其计数与图内可见关系数量分开表达。

## 功能二：本地变更摘要

### 最小使用方式

新增一个本地脚本，输入前后两份统一数据包（与现有preview-data结构相同的`{cards, graph}`），默认输出到终端，可选保存Markdown。它是离线文件对比，不是页面内的新功能，也不调用模型。

建议未来入口：在开发目录执行`./tools.sh npm run changes -- --before <旧数据包> --after <新数据包> [--out <摘要路径>]`。**该命令目前尚未实现。** 正常输出清楚说明比较的两份文件；缺文件、非法JSON、重复ID或无效关系端点等应明确报错并非零退出。正常存在差异不算执行失败。

首次实施时保留升级前数据包作为首个比较样本；后续由维护者明确指定上次接收的版本，不依赖工作区是否干净，也不自动覆盖旧版本。摘要输入不回写任何源文件。

### 摘要内容与比较口径

- 概念新增/删除，按稳定card_id识别；同ID的名称、英文、主题、层级、卡文字段（含通俗解释）修改列出变化字段，长文只给短预览，仍可回查两份原文件。ID变化按删除＋新增处理，不用模型猜“其实是改名”。
- 关系增删以关系类型＋有效端点识别；related端点互换视为相同关系，prerequisite保持方向，反向按删除旧关系＋新增反向关系报告。重排数组或重编号edge_id不能误报知识关系变化。
- 原有裁定状态、来源依据等元数据若变动，单列“记录信息变化”，不静默丢弃；文件时间、数组顺序或构建统计变化不冒充概念/关系变化。未知元数据有差异时同样保留提示。
- 检查节点/卡ID对齐、未知主题、重复关系、无效端点和前置循环；部分主题没有前置边不是错误。数据不合法时不得输出“全部通过”。对比工具不自动修复、不判断新增知识是否正确。

输出示例仅用于说明形式：`修改3个概念；新增2条关系；删除1条前置关系；基础数据检查通过。` 实际数字必须计算。维护记录采用这份摘要＋必要说明，避免每次更新追加长篇验收报告。

## 实现顺序与协作

| 顺序 | 实现范围 | 交付与检查点 |
|---|---|---|
| 1 | 确认版本输入和基线，先实现变更摘要 | 可运行本地命令；相同输入零变化，伪造的小样能准确识别增删改/方向变化及非法输入 |
| 2 | 主题入口、颜色、目录/搜索与三维可见性 | 沿用现有视觉，在HTML中直接调整；完成全部/六主题及主题外概念规则 |
| 3 | 接入历史恢复，运行相关回归并完成独立构建检查 | 重选/快速返回等55—58号路径保留，特别检查“选择主题→读概念→返回” |
| 4 | 交付一个下一版候选与短更新说明 | 变更摘要、通过/未验证项、候选入口；用户查看后再决定正式入口 |

沿用既有合作方式时，Codex负责主题入口与视觉、最终回看；WorkBuddy负责离线摘要及状态/图谱接线、工程验证。执行开始前明确文件归属，同一个控制器按顺序修改，不并发改同一文件。无需新增Agent角色、再做工具选型或长篇分阶段报告；本规划不代表已经向WorkBuddy派发任务。

## 验收与停止条件

1. 全部主题恢复197/1562；六主题数量由axis统计，目录、搜索和图谱一致；主题内每条可见边的两个端点都可见，标签、箭头和键盘入口也一致。
2. 选择主题不重排节点；切回全部、全景、定位、主题外邻居阅读及历史恢复按上述规则执行，URL/selected/history.state/正文一致。原相邻展开、零等待返回、相机/滚动恢复回归通过。
3. 320/390/430px检查选择列表、长名称、零结果及触控热区；至少一次真实点击“选主题→搜索→阅读→图谱→返回”。手机实机另列结果，不以模拟通过替代。
4. 离线摘要对相同、字段修改、关系增删、无向端点互换、有向反转、仅重排序/edge_id变化及非法数据均有小样断言；命令错误时非零退出，输入文件字节保持。
5. 现有专用atlas构建及独立候选实际打开通过；本迭代现有卡文、关系和内容补齐真源不变，新增的主题映射只解释已有axis。

通过上述范围即可停止本轮开发，不自动加路径推荐、自动分群、全文搜索、缓存系统或管理端。当前既有版本仍可回看；本地候选通过、手机实机、内容语义审校、用户接收和正式发布分别记录。正式发布/部署/覆盖G_v2及提交推送不在本次规划授权中。
